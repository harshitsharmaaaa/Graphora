# Eraser — Collaborative Whiteboard (Monorepo Foundation)

Production-grade TypeScript monorepo foundation for a collaborative
diagramming/whiteboard app (Excalidraw / Eraser.io inspired).

> **Scope:** foundation and architecture only. No editor, canvas, auth,
> database, realtime, or AI yet — those land in later phases.

## Stack

| Concern     | Choice                                                                                                                                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Package mgr | Bun (workspaces)                                                                                                                                                                                               |
| Monorepo    | TurboRepo (`turbo run …` across workspaces)                                                                                                                                                                    |
| Frontend    | React 18 + Vite 7 + TypeScript (strict)                                                                                                                                                                        |
| Backend     | Node.js + TypeScript, [Hono](https://hono.dev) (lightweight, TS-first HTTP framework — ~14 kB, zero deps — chosen over Express for smaller footprint and edge-portability later) + `@hono/node-server` adapter |
| Validation  | Zod (`@eraser/shared-validation`)                                                                                                                                                                              |
| Lint/format | ESLint 9 (flat config) + Prettier                                                                                                                                                                              |

## Structure

```text
.
├── apps/
│   ├── frontend/             # Vite + React + TS frontend (port 5173)
│   └── backend/              # Node + Hono backend (port 3001, GET /health)
├── packages/
│   ├── shared-types/         # Dependency-free shared TS types
│   ├── shared-validation/    # Zod schemas mirroring shared-types
│   ├── ui/                   # Shared React components (Button smoke-test)
│   ├── config/               # Shared ESLint baseline + Prettier options
│   └── tsconfig/             # base / frontend / backend / library presets
├── turbo.json                # build/dev/typecheck/lint/test pipelines
├── .env.example              # PUBLIC_* (browser) vs SERVER_* (backend) placeholders
└── bun.lock                  # generated by `bun install`
```

Dependency rules: `apps/* → packages/*` only. Shared packages never import
apps. `shared-types` has no React; `shared-validation` has no frontend deps.

## Prerequisites

- Bun ≥ 1.1, Node ≥ 20

## Commands

```bash
bun install     # install all workspaces
bun dev         # start frontend + backend together via Turbo
bun run build   # build all workspaces (libs first, via ^build)
bun typecheck   # strict tsc --noEmit in every workspace
bun lint        # eslint per workspace
bun run test    # placeholder scripts until real tests land
```

After `bun dev`:

- Frontend → http://localhost:5173 ("Frontend is running", with an API-health button)
- Backend → http://localhost:3001/health returns `{ "status": "ok" }`

Copy `.env.example` to `.env` to override `SERVER_PORT`, `PUBLIC_API_URL`, etc.
`SERVER_*` values are read only by `apps/backend/src/lib/env.ts`; Vite only
exposes `PUBLIC_*`/`VITE_*` to the browser, so backend secrets cannot leak
into the client bundle.

## Workspaces

- **apps/frontend** — Vite SPA. Path alias `@/* → src/*`, typed env in
  `src/lib/env.ts`, smoke-test page imports `@eraser/shared-types`,
  `@eraser/shared-validation`, `@eraser/ui`.
- **apps/backend** — Hono app assembled in `src/app.ts`, started in
  `src/server.ts`. Layers: `routes/ → controllers/ → services/`, plus
  `middleware/` (request logger), `lib/` (env), `types/` (backend-local).
- **packages/shared-types** — types-only, zero dependencies.
- **packages/shared-validation** — Zod schemas (`healthStatusSchema`,
  `exampleEntitySchema`).
- **packages/ui** — shared `Button` component (React peer dep, no UI framework).
- **packages/config** — `eslint/base.js` flat-config baseline, `prettier/base.json`.
- **packages/tsconfig** — `base.json` (strict) extended by `frontend.json`
  (Bundler, `react-jsx`, `noEmit`), `backend.json` (NodeNext, emits `dist`),
  `library.json` (Bundler + `dist` for publish readiness).

## Assumptions

- Workspace scope is `@eraser/*` (not literal `@project/*`).
- Shared packages export TypeScript sources directly (`"./src/index.ts"`),
  which Vite and `tsx` consume without a pre-build; `build` still emits
  `dist/` for publish readiness. A bundled backend artifact for deployment
  arrives with the first deploy phase (`start` runs `node dist/server.js`).
- No test runner is wired yet — every workspace has a `test` placeholder so
  `bun run test` passes through Turbo today; Vitest/Bun test lands with features.
- `bun build` / `bun test` collide with Bun's built-in subcommands, so the
  `run` prefix is required for those two (`bun dev`, `bun lint`, `bun typecheck`
  work without it).
